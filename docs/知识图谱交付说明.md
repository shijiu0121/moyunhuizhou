# 徽史问答官知识图谱交付说明

交付日期：2026-10-13。已在本地完成代码修改与验收，服务器由部署方同步。本包为源代码增量包，目录与项目根目录对应。

## 1. 本次实现

在“徽史问答官”页面右上方新增“探索徽州知识图谱”，地址为 `/ask/knowledge`，属于 `/ask` 路由分组，顶部导航仍高亮“徽史问答官”。页面延续现有宣纸底色、朱砂印章、桥木褐配色、楷体标题和卡片边框。

功能包括主题网络、节点选中与关联高亮、拖动节点和画布、滚轮缩放、复位、主题自动漫游、9 类主题筛选、篇名和全文搜索、可滚动资料索引、原文阅读弹窗、关联资料跳转，以及带问题返回问答。返回问答时只填入草稿，用户编辑、发送后才调用原问答接口。

图谱直接读取与 RAG 相同的 `backend/app/data/*.txt` 和 `*.jsonl`。当前本地 60 篇资料生成 70 个节点、106 条连线，其中 69 条为主题层级连线，37 条为资料间的关键词关联。服务器如果拥有不同的资料，统计会按其实际内容生成。

图谱的含义是“主题与资料阅读网络”。主题由标题关键词整理；跨资料虚线表示两篇原文共同出现至少两个目录关键词，每篇最多两条此类关联。虚线不表示师承、因果、年代或其他经考证的历史关系。资料来源显示真实文件名；知识库未记录统一来源网址，因此没有补造外部出处。

## 3. 选择同步方式

本地仓库开始本任务时已存在未提交修改，本次均予以保留。包中的 `Ask.vue` 与 `api/index.js` 是基于当前本地版本的完整文件，包含此前已有功能。如果服务器与本地版本一致，可采用完整文件覆盖；若服务器还有单独修改，优先采用 `changes.patch`，避免覆盖服务器已有代码。两种方式只选一种。

`changes.patch` 以本次修改前的本地文件为基线，不是相对 Git HEAD 的全部改动，也不包含本任务以外的其他脏文件。应用补丁前运行 `git apply --check`；若上下文不匹配，按补丁人工合并这 8 个运行文件，不要强制覆盖。

### 方式 A：完整文件覆盖

1. 上传 `huizhou-knowledge-graph-20261013.zip` 并解压到独立目录。不要先直接覆盖项目。
2. 在服务器上设置实际路径；以下示例路径需按部署位置填写：

```bash
PROJECT=/root/autodl-tmp/mojyun-huizhou
PATCH=/root/autodl-tmp/huizhou-knowledge-patch
cd "$PATCH"
sha256sum -c SHA256SUMS
```

3. 备份将被替换的 6 个现有文件：

```bash
cd "$PROJECT"
tar -czf "$PROJECT/knowledge-backup-$(date +%Y%m%d-%H%M%S).tar.gz" \
  backend/app/rag/knowledge.py backend/app/routes/ask.py \
  frontend/src/api/index.js frontend/src/router/index.js \
  frontend/src/App.vue frontend/src/views/Ask.vue
```

4. 按相对路径覆盖。包内这些目录仅包含本次功能文件：

```bash
cp -a "$PATCH/backend/." "$PROJECT/backend/"
cp -a "$PATCH/frontend/." "$PROJECT/frontend/"
cp -a "$PATCH/docs/." "$PROJECT/docs/"
```

### 方式 B：应用本次增量补丁

同样先解压、校验并备份，再在项目根目录执行：

```bash
cd "$PROJECT"
git apply --check "$PATCH/changes.patch"
git apply "$PATCH/changes.patch"
cp -a "$PATCH/docs/." "$PROJECT/docs/"
```

补丁包含新增的图谱后端、Vue 页面和测试文件，不需要再执行方式 A 的代码覆盖。

## 5. 服务器验收

后端启动后先检查接口：

```bash
curl -sS http://127.0.0.1:8000/api/ask/knowledge-graph \
  | python -c 'import json,sys; print(json.load(sys.stdin)["stats"])'
```

使用相同的 60 篇原文时，预期输出 `{'articles': 60, 'topics': 9, 'relations': 37}`。若显示全零，检查服务器的 `backend/app/data/` 下是否保留知识原文，而不只是 `vector_store/`。

浏览器从“徽史问答官”进入“探索徽州知识图谱”，依次检查主题筛选、搜索“朱熹”、点选节点、展开原文、漫游与暂停、拖拽缩放、复位、带问题返回。用一条问题确认服务器原 BGE + DeepSeek 问答仍正常即可。

可运行附带测试：

```bash
cd "$PROJECT/backend"
python -m unittest discover -s tests -v
```

知识原文新增或编辑后，刷新图谱即可重新读取；图谱不会修改现有 ChromaDB 索引。原问答索引的维护仍遵循项目原有流程。当前算法适合现有约 60 篇资料的规模；主题和关键词目录可在 `rag/graph.py` 中维护，新标题未命中已有分类时归入“历史人文”。
